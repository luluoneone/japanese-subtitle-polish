### 仕上げの確認（2026-10-06）

- 文字の大きさの見本を、整えるときと同じ改行の決め方に変更。以前は字数で機械的に区切っていたため、「Premiere Pro」の空白が消え、「説明しま／す」のように語の途中で切れていた。直したあと、同じ字幕が「今回はPremiere Proの／Lumetriカラーで説明します」になることを画面で確認
- 2行に収まらない字幕は、見本と確認画面の両方で、枠の中で折り返して表示し、「収まらない」と知らせる（以前は枠の外にはみ出して切れていた）
- 確認画面の「確認が必要」から、読む速さの超過を外し、「目安より速い」として別に絞り込めるようにした。サンプル02（14件）を 1秒4字 で整えると、以前は「確認が必要」が7件だったが、2件（要確認1・行の上限超え1）になった

## 7. 機械検査で確かめたこと・確かめていないこと

**確かめたこと（verify_srt.py）**：字幕の件数・番号・順番、時刻行のバイト一致、字幕の間の空行、BOM、改行コード、本文が変わった字幕が適用ログと一致すること、元のSRTと修正版のSHA-256。

**確かめていないこと**

- 日本語の意味：サンプルと別AIの結果は作者が読み、数字・否定・口調・固有名詞が変わっていないことを目で確認しました。第三者による確認はしていません。
- 読みやすさ：改行は作者が読んで、語の途中で切れていないことを確認しました。次のような判断の分かれる改行は残っています。
  - 「あの人に二、三回教えてもらった／だけで世界が変わりました」（「だけで」が行頭）
  - 「ログ素材には／変換用のLUTを先に当てます」（上下の長さの差が大きい）
  実際の動画に字幕を重ねての確認はしていません。
- 映像との同期：時刻を変えていないことだけを確認しています。音声との一致は確認していません。
- 実際の Whisper・Premiere Pro・CapCut・DaVinci Resolve の書き出しファイル：サンプルはそれらを模して作ったもので、実ファイルでは試していません。
- 修正版を編集ソフトへ読み込めるか：試していません。
- Windows：2026-10-12 に Parallels の Windows 11（ARM）で、Python のない状態からの導入・テスト・基本の流れを確かめました（10章）。Intel 版 Windows の実機と、Windows でのローカルAIは試していません。別の Mac への新規導入も試していません（コードは標準ライブラリだけで、改行コードと文字コードはOSに依存しない書き方にしています）。

## 8. 分かっている制限

- 改行は形態素解析を使わない規則ベースです。ひらがなが続く部分で、まれに不自然な位置で切ることがあります。
- 安全チェックは、意味を変えやすい修正を止めるための目安です。誤って止めることがあります（例：「説明しまう」→「説明します」は語尾の変化として止まり、利用者の承認が必要）。逆に、チェックを通っても意味が保たれたとは限りません。
- 1行の文字数は、全角1・半角0.5の目安で、フォントの実際の幅は測っていません。確認画面の字幕の大きさも目安です。
- 確認画面の決定は、そのブラウザの中にだけ記憶されます。別のブラウザ・パソコンには引き継がれません。
- 字幕の分割・結合、時刻の調整は行いません。長すぎる字幕は報告だけです。
